# Implementation — Azure Policy & Governance

This folder documents the hands-on implementation of an enterprise-style Azure governance framework using Management Groups, Azure Policy, RBAC, resource tagging, resource organization, monitoring, networking, and cost governance.

---

## 1. Management Group Hierarchy

Implemented an enterprise-style Management Group hierarchy to provide centralized governance and policy inheritance.

### Hierarchy

Tenant Root Group
└── landing-zones
    ├── Development
    │   └── Learning-labs
    ├── Production
    ├── Platform
    │   ├── Connectivity
    │   ├── Identity
    │   └── Management
    └── Sandbox

### Governance Objective

Management Groups provide a hierarchical scope for applying:

- Azure Policy
- RBAC
- Governance standards
- Compliance controls
- Subscription-level governance

Policies assigned at higher scopes can be inherited by child Management Groups and subscriptions.

## 2. Resource Group Organization

Created functional resource groups following an enterprise naming convention.

| Resource Group | Purpose |
|---|---|
| `rg-platform-network-dev` | Networking resources |
| `rg-platform-identity-dev` | Identity-related resources |
| `rg-platform-management-dev` | Management and governance resources |
| `rg-shared-services-dev` | Shared platform services |
| `rg-workload-app1-dev` | Application workload resources |
| `rg-monitoring-dev` | Monitoring and Log Analytics |

### Naming Convention

`rg-<function>-<workload>-<environment>`

Example:

`rg-platform-network-dev`

This improves resource discoverability, operational management, automation, and governance.

## 3. Azure Policy Governance

Implemented Azure Policy-based governance controls to enforce organizational standards.

### Governance Controls

The environment includes policy controls for:

- Allowed Azure regions
- Allowed VM SKU sizes
- Required resource tags
- Tag inheritance
- Resource compliance
- Deny-based governance controls
- Audit-based governance controls

### Policy Effects

| Effect | Purpose |
|---|---|
| Audit | Identifies non-compliant resources |
| Deny | Prevents non-compliant deployments |
| Modify | Automatically modifies resource configuration |
| Append | Adds required configuration |
| AuditIfNotExists | Verifies required related resources or configuration |

## 5. RBAC Governance

Reviewed and configured Azure Role-Based Access Control at subscription and Management Group scopes.

### RBAC Principles

The implementation follows:

- Least privilege
- Scope-based access
- Role separation
- Privileged access awareness
- Inheritance management

### Example Roles

- Owner
- Contributor
- Reader

Azure RBAC assignments were reviewed through:

`Subscription → Access control (IAM)`

The implementation also demonstrates inherited role assignments from higher governance scopes.
